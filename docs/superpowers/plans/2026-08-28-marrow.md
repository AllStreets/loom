# Phase 22 Implementation Plan — Marrow

> **For agentic workers:** checkbox steps. Spec: `docs/superpowers/specs/2026-08-28-marrow-design.md` (authoritative). Recon facts: `tauri dev` does NOT watch `src-tauri/**` (vite.config.ts `server.watch.ignored: **/src-tauri/**`), so Rust edits need a restart — no hot-reload. `boot_recover` runs inside `.setup()` in `src-tauri/src/lib.rs:~32` (AFTER Builder construction) — a Rust edit that panics before that bypasses recovery; this phase moves rollback EARLIER + adds a pre-compile guard. Reuse Phase 21: `src-tauri/src/kernel.rs` (is_editable + PROTECTED/PROTECTED_PREFIXES, propose/validate/approve/apply, Sentinel + boot_recover/decide_boot_at), `exec.rs` (run_checked hardened spawn), `src/lib/loom/kernelBuild.ts`, `src/components/chrome/KernelDiff.tsx`. cargo validation in a worktree is minutes (no shared target/) — honest slow UX.

**Goal:** LOOM edits its own Rust core in dev, behind the five walls, with the recovery gap CLOSED (pre-compile guard + pre-main rollback + confirm beacon) so a compile-clean-but-panics edit self-heals on restart with zero manual git. Packaged self-rebuild deferred.

**Tech stack:** existing only (git2, std::process, node). No new deps.

## Global constraints
- **Never strand the owner.** The gap-closure is mandatory and its logic is tested. A Rust edit that panics at startup must self-heal on the next `tauri dev` start (source reset before recompile).
- **Self-protection extends to Rust:** the whitelist now allows `src-tauri/src/**/*.rs` MINUS `PROTECTED_RUST` (the safety core + entry + Cargo manifests + the guard script). Enumerated test. Any file that constructs the app / runs before recovery / implements a wall MUST be in PROTECTED_RUST.
- Hardened spawn discipline (exec.rs) unchanged; cargo runs fixed-argv, cwd under the worktree, longer timeout.
- Tokens only; BRAND voice; honest "restart to load" + "editing the core" framing. Gates: `npm run check` green per task.

If the sentinel shows the last applied edit's boot was never confirmed healthy (status `applied`/`booting`, not cleared), run `git reset --hard <prevSha>` on the source repo and rewrite the sentinel to `healed`, logging a calm line.
